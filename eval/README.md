# AgentGuard evaluations

Full results with every table: [RESULTS.md](RESULTS.md) (generated by `python -m eval.report` from `results/`).

## Method
- **E1, red-team.** The locked suite v1 (55 attacks, 55 legitimate tasks) and three locked held-out attack sets
  (model-written 18, external 6, owner-sourced 5) run through the MIT runner in `redteam/runner/` under configs that add
  one layer at a time: no guardrails → policy as locked → price check and fuzzy sanctions → injection check → AML
  monitoring with AML→hold → pre-payment split check. Code is frozen and tagged (`eval-freeze-1`, `eval-freeze-2`)
  before held-out sets run; each held-out set runs once per config and only aggregates are saved.
- **E2, IBM AML HI-Small** (synthetic public benchmark, CDLA-Sharing-1.0, not redistributed; place it in `data/ibm-aml/`).
  First 7 days, bank-scale settings fixed before reading labels, compared with a $10,000 amount threshold, with and
  without a daily alert budget. Round 2 retunes only the rapid-fire rule on days 1–3 and tests on days 4–7.
- **Latency** measured in the E1 runs; **look-alike false positives** on the SEC `company_tickers.json` registrant list.
- Anything built after a lock is labelled **added after lock** and shown next to the config without it.

## Reproduce
```
python -m eval.run_e1            # Stage 3 configs (needs GROQ_API_KEY for the injection check)
python -m eval.run_e1_round2     # split check
python -m eval.e2_ibm --days 7   # IBM benchmark
python -m eval.e2_rapidfire_tune # rapid-fire retune
python -m eval.lookalike_fp      # needs data/sec/company_tickers.json
python -m eval.report
```

## Limitations
- Money is SIMULATED; no real payments are made.
- The IBM data is synthetic; bank transfers are not agent payments, so the rules run through a shim.
- The suites are small. Held-out sets contain no legitimate tasks, so false blocks are measured only on v1's 55.
- The injection dev set (30 items) was written by the builder. The held-out sets were written by models; the owner set was
  drafted with Claude, the builder's model family. None is fully independent.
- Groq was called directly instead of OpenRouter (no OpenRouter key); same model.
- Charts are planned for the Stage 4 results page.
